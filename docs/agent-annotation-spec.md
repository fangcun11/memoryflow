# MemoryFlow 知识块标注规范（Agent 创作契约）

> 本文档是 AI agent 编写知识库材料时必须遵守的标注规范。标签语法是唯一权威格式；旧符号语法（`**名解**`、`{{填空}}`、`?选择`、`!判断`）仅作为历史数据别名，agent 不得再产出。

## 1. 总体结构

材料是普通 Markdown 文本：

- `#`~`####` 标题行用于分块与命名；
- 空行分隔段落；单个知识块建议 **80–250 字**（超 300 字会被强制切分，跨块的 `<choice>` 等结构会被保护不切断，但仍应避免）；
- 标注以内联/块级标签嵌入正文。

## 2. 标签注册表

| 标签 | 用途 | 出卡 |
|---|---|---|
| `<recall hint="提示">术语</recall>` | 名词解释重点 | recall 卡（正面=术语，背面=所在块原文） |
| `<cloze group="1">关键词</cloze>` | 填空 | 每组一张卡，正面只挖本组 |
| `<choice stem="题干">…</choice>` | 选择题 | choice 卡（选项展示时自动洗牌） |
| `<judge value="true\|false">陈述</judge>` | 判断题 | judge 卡 |
| `<idiom cmp="易混项">成语/术语</idiom>` | 成语/概念辨析 | recall 卡（背面附易混对比） |
| `<hl color="amber\|teal\|blue\|coral">内容</hl>` | 高亮强调 | 不出卡 |
| `<note>批注正文</note>` | 批注/旁注 | 不出卡（渲染为角标） |

## 3. 选择题结构（多行块级标签）

```xml
<choice stem="认识过程的两次飞跃是">
<opt correct>从实践到认识、从认识到实践</opt>
<opt>从感性到理性、从理性到实践</opt>
<opt>从具体到抽象、从抽象到具体</opt>
<explain>两次飞跃指实践→认识、认识→实践（可选）</explain>
</choice>
```

- `<opt correct>` 恰好一个；干扰项 ≥1，干扰项要有迷惑性而非明显错误；
- 题干放 `stem` 属性，标签体内只放选项与解析。

## 4. 判断题

- `value="true"`：陈述为真（默认，可省略属性）；
- `value="false"`：陈述为假（否定式干扰陈述）。

## 5. 硬性规则（违反会被 lint 拦截）

1. 标签必须闭合；属性值用双引号；
2. `<choice>` 内 `<opt>` ≥ 2 且 `<opt correct>` 恰好 1 个；
3. 不要发明注册表之外的标签（如 `<Recall>`、`<clozes>`）——未知名标签会被 `lintAnnotations` 报告；
4. 标签内不要再嵌标签（v1 不支持嵌套）；
5. 正文中的 `<` `&` 直接写有解析风险，尽量避免；确需表达用中文标点替代；
6. 一张卡对应一个考点：单卡最小化，宁可多块多卡，不要把多个知识点堆进一个块。

## 6. 自检

写完后调用 core 的 `lintAnnotations(content)`：

- 返回 `[]` 表示通过；
- 常见告警：未知标签、未闭合、`<opt correct>` 缺失或多个。

## 7. 书写风格建议（影响卡片质量）

- `<recall>` 圈术语本身，不要圈整句；
- `<cloze>` 挖"唯一确定答案"的词（数字、术语、并列项）；同类并列项用 `group` 分组，一组一张卡效果最好；
- 高亮 `<hl>` 用于金句、易错眼；批注 `<note>` 写给未来的自己（为什么重要、怎么考）；
- 辨析类一律用 `<idiom cmp>` 或独立对比块，不要挤进同一段。
